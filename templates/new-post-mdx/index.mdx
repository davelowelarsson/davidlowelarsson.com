Open with the point — the first paragraph is what feeds and previews show.

## Use h2 for sections (the page owns h1)

Everything in the `.md` template works here unchanged: prose, lists, tables,
blockquotes, fenced code, and `mermaid` diagrams. What `.mdx` adds is
**components** — the component tier of the figure contract.

A component is imported once, above the body, and then used below. The
`../../../../` counts out of `src/content/posts/<year>/<slug>/`:

<ArticleLinks
  title="Further reading"
  links={[
    { label: 'A source', href: 'https://example.com/', description: 'Why it is worth the click.' },
    { label: 'All posts', href: '/posts/', description: 'Internal links do not open a new tab.' },
  ]}
/>

### Media needs an imported asset

Colocate the file in this folder, import it, and pass it in. Uncomment both
lines together — an import of a file that is not there is a build error:

{/* import myImage from './my-image.png'; — move this up beside the other imports */}

{/* <ArticleImage src={myImage} alt="What the image shows" kind="photo" /> */}

`kind` is required and says what the media **is** — one of `diagram`, `chart`,
`screenshot`, `photo`, `sketch`, `embed`. Add `breakout` to run wider than the
reading measure, and `caption` for a line beneath it. Both are component-only.

A plain Markdown image still works here and is still the right default. It gets
framing from its path, but never a caption and never a breakout:

{/* ![What the image shows](./my-image.png) */}

## Which template do I want?

Use `.md` unless you need a component. Most posts do not — the overwhelming
majority of the site's images are plain Markdown. Reach for `.mdx` when you want
a **caption**, a **breakout**, the **screenshot** plate, a video, a YouTube
embed, or a side-by-side aside.

The full catalogue of what each tier can render, with a copyable snippet beside
every example, is the kitchen-sink Fixture:

- `src/content/posts/2026/kitchen-sink/index.mdx` — the component tier
- `src/content/posts/2026/kitchen-sink-markdown/index.md` — the Markdown tier

Both are permanent drafts, so they render on any Preview Deployment at
`/posts/kitchen-sink/` and `/posts/kitchen-sink-markdown/`.

## How to use this template

```sh
cp -r templates/new-post-mdx src/content/posts/2026/my-post-slug
# edit src/content/posts/2026/my-post-slug/index.mdx
# push a branch, open a PR, check the preview URL comment
```

A post bundle holds **exactly one** `index.md` *or* `index.mdx`, never both —
the collection derives a post's identity from its folder name, so two index
files in one folder are two posts claiming the same URL. That is why this is its
own directory rather than a second file inside `templates/new-post`.
